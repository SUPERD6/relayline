- Fix: on Windows, every Claude sub-agent failed to start with `[WinError 206]` when its `--settings` JSON (hundreds of
  deny rules from `CCX_CLAUDE_SETTINGS`, e.g. an evaluation's forbidden folders) passed 32767 characters (#585). Past
  6000 characters ccx now writes the JSON to `claude-settings.json` in the run's folder and passes its path to
  `--settings` (checked on claude 2.1.316: a file path works, 52 KB run fine); short settings stay inline as before.
  The credential guard reads and rewrites that file, and only ccx's own (an arbitrary settings file is still refused).
- A sub-agent whose process cannot be started (any `OSError` from the launch) now ends the run as `kind: env` with
  `needs_lead` ("ccx launch failed: ..."): no climb, no retry, no fallback, nothing is read as a wrong answer.
  Any `OSError` at launch counts, also a temporary one (no memory, no handles): it is not retried.
  The settings file denies Read/Edit/Write/Bash on itself, so a sub-agent cannot change its own rules.
  Codex was not affected: its prompt goes through stdin and its long arguments are checked by the credential guard,
  which refuses (a clear error) instead of launching past the limit.
