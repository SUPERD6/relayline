三步上手

  1. 安装pipx install git+https://github.com/SUPERD6/relayline（也可以先 ccx demo，不用账号）。
  2. 接好ccx setup 把 ccx 接进 Claude Code 和 Codex；每一步都说明，改东西之前先问你。
  3. 派活在 Claude Code 里说：“通过 ccx 交给 Codex，用 pytest -q 验收”。然后 ccx ui 看收据。

八层

一次派活走过全部八层。每层：ccx 做什么、一个实测数字、一个限制（实测）。全部命令和选项（含 ccx ask、ccx send、ccx batch、ccx agents、--review 和推断判断）见功能说明。子智能体不能再经 ccx 往下派活；改配置前先预演、先备份。

① 对话

ccx discuss 让两三家各给意见；对话板（ccx say、ccx reply）让开着的会话互相留言。还没实测；Claude Code 当主导时要到下一轮才看到消息。

② 共享记忆

你的 hub 和项目的 .ccx/；跟任务有关的便签自动写进每份说明；ccx handoff 交接。项目便签被遵守 9/9，没有便签 0/9；3 个任务 × 3。

③ 拆分与流水线

ccx q：持久的工作队列，每块一个 worktree，按依赖合并。小任务交给 Codex 的对照里，主导每个任务都少发一次请求，21/21，但总花费基本持平、token 3.3 倍。

④ 派活与选人

ccx route 选派给谁、什么模型和 effort，或者直说自己做更便宜。仓库任务每次成功 $0.063，自己做 $0.090；小题贵 3.1 倍。

⑤ 验收与收据

ccx 自己重跑你的 --check，另一家审查改动，你给结论；收据写明 check 覆盖了什么。隐藏测试下做对 29/30；跑子智能体自写测试的 check 把 pg1 做错的 18 题全判过；现在这种通过记为自写测试通过并送审（还没重测）。

⑥ 控制与恢复

ccx stop、ccx resume、ccx undo、--worktree、自主度 L0–L2。只靠交接文件，下一个智能体接上 3/3（受控运行）；一个真实长会话起初失败。

⑦ 测量与诚实

跨厂商一本账、评测前查干净环境、公开基准、负结果也发布。一次运行上 API 等价花费与 Claude 自报差 1.5%；订阅用户付的是额度。

⑧ 界面与上手

ccx ui：一个项目一张图；ccx demo 不用账号；ccx setup、ccx doctor。还没做用户研究；我们自己测试之外的真实使用还很少。

怎么连起来的

  1. 打分改几个文件、跨几个模块、目标清不清楚、风险、要不要新设计 → 难度 0–10。
  2. 选档成功率够高的档位里挑最便宜的；不值得派就让你自己做。
  3. 运行另一家在你的文件夹里后台干活；ccx 重跑验收命令，可选另一家审查。
  4. 验收你看一眼 diff，再 ccx verify；选模型按结果校准。

常见问题

多一个智能体，不是更费 token 吗？

有可能。实测里，小任务上主导看到 ccx 验收通过就直接答复，少发一次请求，但总花费基本持平；主导再自己跑一遍测试，就是多花子任务的钱、多等十几秒。钱主要花在主导每轮重读自己的对话上，ccx lead、ccx sum、ccx fresh 管的是这一块。

我用的是订阅，不是 API，也适用吗？

适用。花费按 API 价格折算，方便比较；看板也会显示每个工具的额度用在了哪里。一边额度用完了，任务会换到另一边（目前只有模拟测试）。

让子智能体改文件安全吗？

只能改任务所在的文件夹；每次可写运行都会拍快照，可以 ccx undo；--mode read 或 --worktree 不会动你的工作区。详见 SECURITY.zh.md。

支持哪些工具？

Claude Code、Codex、DeepSeek（dsh，或经 Claude Code）都可以当主也可以当子，真机测过。Gemini CLI 按文档写了适配器但没真跑过，只能当子智能体；经 Claude Code 的 Kimi、GLM、Qwen、OpenRouter 配好了，没测过。

名字为什么改了？

原名 claude-codex-bridge 和另一个项目（SeemSeam/claude_codex_bridge）几乎同名，而且现在不只两家。命令仍是 ccx，旧地址会自动跳转。
