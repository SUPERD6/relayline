# 实验性简报检查

[English](brief-check.md)

`ccx run` 启动智能体前（包括 `--bg`）会做便宜的静态检查，提醒明确冲突：
只读模式却明确要求改文件或建 PR；用 `Read`、`Inspect`、`Open` 明确要求读取的本地
输入不存在；`--check` 或以 Run 开头的反引号内联命令使用明显不适合当前原生平台的语法。
也识别部分中文读取、改文件指令。不调用模型、网络或命令，不读取文件内容。

默认只在 stderr 警告，并在收据和保存的运行记录中新增 `brief_warnings` 数组，
`ccx show` 和后台启动收据也保留它。不改变路由、权限、判定和退出码，不移除已有命令或选项。
后台子进程保留诊断，但不重复打印父进程已给出的警告。
**阻止派活默认关闭**；加 `--strict-brief` 后，有警告就输出拒绝收据
（`delegated: false`）、退出 2，不启动智能体或后台进程；无警告则正常运行。
没有新增配置键。

检查使用最终确定的模式、原始简报和目标 `--cwd`，先于项目、角色与共享上下文包装。
这是保守启发式，未识别的说法和命令属于 Unknown。要创建的输出路径不必已存在。
修改建议、否定指令、可选输入、URL、通配符、占位符、其他平台的绝对路径和工具私有路径
会跳过，也跳过围栏代码块和引用块（即使里面包含真实指令）。
输入路径遇全角标点截断；没有目录分隔符的名称只识别 `.py`、`.md`、`.json`、`.txt`
等常见扩展名，避免把 `os.path`、`3.11` 当作文件。`写一个报告文件` 和
`Write the report to out.md` 会触发只读模式冲突；只要文字报告或否定写入的要求不会。
显式 `bash`、`wsl`、`powershell`、`pwsh` 包装不推测内部兼容性；不推测已安装工具
或 shell 版本。Windows 检查走原生命令 shell，因此单独出现 `&&` 不算平台冲突。

证据仅为假 CLI 工程检查；对真实简报的有效性与误报率为 **Unknown**。
