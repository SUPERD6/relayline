# 实验性短任务主导精简

[English](lead-slim.md) · 中文

`[lead] slim_small = false` **默认关闭**。用 `ccx config set lead.slim_small true` 开启。
运行 `ccx sync --only memory --apply` 更新已有受管块；正常的 `ccx turn` 钩子也会给出指令。
两处都调用 `ccx.lead_slim.small_guidance`，子智能体的钩子不输出它。
关闭时运行 `ccx config set lead.slim_small false`，再同步一次，移除受管块里的指令。
已经打开的对话可能仍保留旧指令；切换后用新会话核对。

开启后，主导已有信息能确认是小活时，直接实现并检查，不先调用 ccx、不写 brief、不加载派活技能。
沿用 `routing.small_self_files` 的文件数限制（默认 1 个实现文件）。这是给主导的指令，不增加硬性拒绝。
文件数不确定、需要 ccx 的 worktree/undo/resume/另一厂商支持、主导上下文大或已知额度紧张时，仍走正常派活。
上下文和额度阈值沿用现有配置。已选档位、按成本判断小活时不输出捷径指令，仍由原路由决定。
不会为这个捷径额外查额度或上下文；不知道大小不等于小活。

命令、选项、JSON 含义、退出码、拒绝绕过方式、验收、审查与升档规则均保留。
实际调用 `ccx run` 时仍按原行为运行。指令存在不能证明模型会照做，也不能证明路由决策完全相同。

证据为 **engineering check**，尚无省钱实测。r5 可选组 `ccx3cand` 开启阶段 3 的候选开关和本开关，
使用压缩指令，保留相同的派活命令及检查、审查、等待、验收行为。这是提示词与配置一起改变的实验。
小活捷径不会写 `small_self_run` 账本事件；没有事件时保持 null/Unknown，不伪造主导的判断。
`fresh2` 新题和历史开销分析见[交付报告](research/2026-11-05-lead-slim.zh.md)。

## 实验性最短启动上下文（#287）

新增独立开关 `lead.slim_context = false`，**默认关闭**。`slim_small` 改小任务指令，
`slim_context` 控制自动上下文。用 `ccx config set lead.slim_context true` 开启，再运行
`ccx sync --only memory --apply`，新开对话。关闭时用同样命令把值设为 `false`。
已打开的对话仍保留读过的内容。尚未做真实客户端节省实测。

受管快照模式下，Claude/Codex 及其他主导的记忆块只留两行：ccx 帮助 / agent-delegate 技能入口，
以及按需加载上下文的命令。块内帮助和上下文命令展开为实际 Python / ccx 路径，ccx 不在 PATH 也能使用。
不再导入或内联快照，也不自动输出 `slim_small` 指令。SessionStart（包括 Claude 插件）仍运行
`ccx mem delta`；受管快照模式不再输出，避免重复入口。只有外部快照模式在 SessionStart 输出两行入口，
两个命令与受管块一样展开为实际 Python / ccx 路径。UserPromptSubmit 的 `ccx turn` 不再推送记忆、
交接、未完成任务、留言板消息、共享上下文和建议，但**保留简短的后台运行完成通知**。
旧版 `ccx lead --hint` 不输出内容。被隐藏的上下文不推进读取游标。

启动静默维护照常执行：概率判定与能力更新、会话归档、项目目录刷新和基准刷新保留原有开关、执行顺序和
失败隔离；`--peek` 和子智能体启动仍跳过这些维护。每轮钩子仍记录人类留言板轮次（读取留言板以重置机器
对话循环限制），并按原配置启动后台留言板同步，但不消费被隐藏的留言。

用 `ccx mem delta --as claude --full`（或 `codex` / 其他主导）主动加载完整启动上下文；
`--peek` 仍表示不推进游标。留言板用 `ccx board`，其他会话用 `ccx peek`，完成状态用
`ccx show` / `ccx q ls` 查询。交接和上下文需要主动加载；后台完成推送保留原来的开关和会话匹配规则。
现有命令、选项、JSON 含义、退出码和判定规则均保留。开关关闭时，受管文本与钩子输出保持原样。

**边界：**技能仍安装并可发现。技能名称和描述由客户端列入上下文，不是 ccx 钩子输出；
本开关不隐藏这些元数据，不改技能正文，正文仍按需加载。外部快照（`snapshot_mode = "external"`）
和个人/项目规则归原加载机制所有，不改写、不抑制。因此精简的是 ccx 受管块与钩子，并非客户端全部提示词。
已有 `layout.skills_include` / `skills_exclude` 可在安装时限制链接；本实验不移除技能链接，
也不接管插件的技能列表。
