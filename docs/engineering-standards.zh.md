# 工程标准

[English](engineering-standards.md) · 中文

这是改动、评测、收据说明和对外说法的长期规则。贡献流程见 [CONTRIBUTING](../CONTRIBUTING.zh.md)，
项目规则见 [AGENTS](../AGENTS.md)。本轮工作见[优化计划](research/2026-11-04-optimization-plan.zh.md)。
本文不改代码或默认值。

## 1. 证据与判定

文档、PR 和收据说明统一用以下标签。证据等级和判定分别写。

| 证据等级 | 所需证据 | 能说明什么 |
|---|---|---|
| **measured** | 真实 CLI 真跑，有数据文件和报告 | 报告条件下观察到的结果 |
| **engineering check** | 测试、假 CLI 或回放 | 只证明代码按设计工作 |
| **not run** | 没有执行 | 不能声称已有结果 |

对明确标准的判定只用 **Pass / Fail / Unknown**。证据缺失或不足就是 Unknown。
说“做完”“修好”或“有效”时，必须说明证据等级和适用范围。这些报告标签不重命名现有 JSON 值、收据类型或退出码。

## 2. 指标定义

评测只用这些定义。改定义前先写决定，格式见[决策记录](../changes/README.zh.md)。

| 指标 | 定义与报告规则 |
|---|---|
| 做对 | 隐藏测试全过。子智能体自写的测试不能证明做对。 |
| 完成率 | 完成单元数 / 尝试单元数。开跑前写明完成标准，与正确率分开报。 |
| 正确率 | 做对数 / 尝试单元数。写分子和分母，不能只看已完成单元。 |
| 每成功成本 | 全部尝试总花费（含失败）/ 做对数。包括主导、子智能体、审查和修复花费。金额标明 API 等价美元。做对数为零时写总花费，不报有限的每成功成本。 |
| 墙钟 | 每个单元从开始到结束的中位数，同时报累计墙钟。人等待的时间可另报，不能替代这个指标。 |
| 收据误报 | 普通 `ok` 且隐藏测试失败。报失败数 / 普通 `ok` 收据数。`ok_self_checked` 单独统计。0/n 同时给 95% 上界及其方法；n = 0 是 Unknown。 |
| 审查抓错率 | 实际错误中被审查拦下的数量 / 全部实际错误数。 |
| 审查误拦率 | 实际正确中被审查拦下的数量 / 全部实际正确数。 |
| 环境干净程度 | 存在 `env_clean=false` 的行时，全部行和干净行两个口径都报，并写各自分母。 |

不能把缺失结果或零分母悄悄当成零错误。保留 Unknown。

## 3. 评测规则

- 开跑前提交预登记。写定代码 pin、题目、组别、轮数、指标、门槛、判定顺序、预算上限和中断处理。
  开跑后不改门槛。
- 分开发集和最终集。调参只用开发集，不能用最终集调参。用过的题要标明，不能算没见过。
- 比较必须同版本、同条件。旧结果标“历史”，不能当当前版本的对照。
- 一次只改一个主要因素。做不到就写明没有分开。
- 评测用独立 clone，机器空闲时跑，一次只跑一个评测。
- 失败和中断都保留、都入账，包括花费。
- 对外数字至少两轮；一轮只算信号。
- 同一项最多改两轮。两轮不过：默认关闭，或只在证实有效的场景开启，并公开负结果。

## 4. 功能规则

- 新行为默认关，门槛过了才默认开。默认值变化要写决定并链接报告。
- 只有 engineering check 的功能标实验性。
- 按 [AGENTS](../AGENTS.md) 保留命令和选项。不再投入的功能保持关闭、标实验性，不继续花钱。
- 保持现有 JSON 字段含义、退出码和判定规则；只能新增字段。改这些约定须先写决定。

## 5. 代码规则

这些规则补充 [CONTRIBUTING](../CONTRIBUTING.zh.md)，不替代其中的流程。

- 只用标准库，兼容 Python 3.11+、Windows、Linux 和 macOS。
- 新逻辑优先放小模块，不继续把 `ccx/delegate.py`、`ccx/ui.py` 变大。单个 PR 一个主题。
- 配置键变化时，同时更新 `ccx/config.py`、`config/tiers.toml` 和文档。
- 环境错误和任务失败分开归类。环境错误不升档，不算任务做错；仍保留在全部行记录和成本账目中。
- 修 bug 要有不修就失败的回归测试。测试用假 CLI，不依赖时钟、执行顺序和机器环境。
- 日志和报告不放凭据、个人路径和个人数据。

## 6. 交付规则

- 测试输出写文件，看汇总行和测试进程的真实退出码，不看后续管道命令的退出码。
- PR 正文写：做了什么、为什么、证据等级、未验证范围、保留了什么。
- 统筹验收看 diff 和原始结果，不只看标题或自评。
- 合并后核对 main 的 CI，清理已合并分支和 worktree。清理遵守下方文件规则。

## 7. 对外说法

- 每个数字带样本量、版本、日期、限制和报告链接。
- 没有同版本对比，不说更快、更省或更准。
- 负结果和正结果一起公开。

## 8. 文件和上下文卫生

说明每次会话自动读取什么。下表是基本预算；客户端特有的额外启动输入也要列明。
这是维护上限，不代表代码已经实现自动截断。

| 文件 | 读取规则与上限 |
|---|---|
| `AGENTS.md` | 由智能体客户端加载的项目规则；最多 8 KB。`CLAUDE.md` 指向它。 |
| `docs/STATUS*.md` | 当前中英文状态文件各一页，不主动读取。需要选工作时才读当前状态；只为相关历史读归档。 |
| `.ccx/handoff.md` | 存在且与恢复工作有关时读取的上次会话交接；最多 8 KB。无关任务不加载。 |

超预算就把旧内容移到归档，只留下一步需要的内容。文件只是放在磁盘上，不被读取就不会进入上下文。

- 交接只写当前状态、下一步和未验证项。旧历史放归档，不往后无限追加。
- 仓库跟踪文件不放可再生产物和本机数据。单个二进制图片超过 300 KB 要说明理由。
- 本地数据按类型处理：可再生的可清理；评测结果和报告先归档；含凭据的目录不打包、不外传。
- 清理前先看内容，先移到归档，记录来源和原因。永久删除由维护者本人决定。
- 不用的旧配置键要么迁移，要么在 `ccx doctor` 中提示，不静默保留。
- 大项目结束或发版时做一次卫生检查，结果写进交接。

## 9. 停下问人的情况

超预算、需要凭据、对外发布、改 GitHub 设置、改历史或不可逆操作前，停下问维护者。
判定规则确实有歧义时也停下。不要自己挑对结果有利的解释。
