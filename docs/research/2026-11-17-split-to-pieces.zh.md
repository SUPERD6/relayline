# 设计说明：自动拆任务拆到"块"为止

[English](2026-11-17-split-to-pieces.md) · 中文

**状态：设计说明，不是决定，也还没实现。** 这里为以后的自动拆任务（从一句话任务到拆成能检查的块并派出去）先写下一条分工边界。
不改代码、默认值或评测。放在 `docs/research/` 而不是 [DESIGN](../DESIGN.zh.md)，是因为 DESIGN 描述 ccx 现在怎么做，
而这里说的拆任务流程还不存在；等实现了，这条边界随实现一起写进 DESIGN。

## 分工边界

| ccx 决定 | 工具自己决定（Claude Code、Codex 等） |
|---|---|
| 派不派，还是主导自己做 | 一块活内部怎么做 |
| 一块活交给哪家、哪个模型、哪档强度（自动选模型） | 这块活里开不开、开几个原生子 agent |
| 一块多大、声明哪些文件、验收命令、依赖关系、哪些块并行 | 步骤顺序、先读哪些文件、过程中怎么测 |
| 一块运行期间的花费和额度上限，结束后的验收（检查、审查） | — |

一句话：**ccx 拆到"块"为止，并决定每块谁来做；块内部由工具按自己的方式做。** 用户可以用角色表或参数固定 ccx 的任何一项选择；自动只是默认。

## 理由

- ccx 知道单个工具不知道的东西：别家的价格、每家剩多少额度、账本里每个模型在各类任务上的历史成绩。这正是"派不派、派给谁、一块多大"需要的输入。
- 块内部，工具最了解自己；它的原生子 agent 不需要交接（不写简报、不重新启动 CLI）。用户要求最大程度用各家的原生能力。
- 在简报里规定微观步骤没有证据说明有用，写这些还要花主导的 token。

## 对后续工作的含义

- 自动拆任务（在现有的 `ccx plan` 拆任务助手上扩展）输出的每块只到这一层：范围、声明的路径、验收命令、依赖、预计时长、建议档位，不再更细。
- 派之前做结构检查：每块有能运行的验收命令；声明的路径不重叠（或写明依赖）；依赖无环；每块不超过时间跨度上限。
- 用一个测试保证简报里不写块内部"先做这个、再做那个"的步骤清单。
- 块内部要不要用原生子 agent 不是 ccx 的配置项。ccx 对原生子 agent 的比较是之后另一组对照，不由这条边界决定。

## 不在本说明里

一块的具体大小上限和自动拆任务怎么评测，留给它们自己的设计和预登记。这里没有任何实测。
