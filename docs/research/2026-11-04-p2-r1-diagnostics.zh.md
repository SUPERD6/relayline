## 4 次确认究竟发生了什么

| 单元 | 确认 run ID | 原始结果 | 判断 |
|---|---|---|---|
| 5 | `20261104-151218-1e89` | `error_max_budget_usd`，$0.0654567；无可用结构化结果 | 预算导致 Unknown，不能当作已排除实现错误 |
| 8 | `20261104-151336-e51c` | 明确指出测试预期与题面规则不一致 | 保留 Unknown 正确，不应拦实现 |
| 9 | `20261104-151407-521f` | `error_max_budget_usd`，$0.0504009；无可用结构化结果 | 同单元 5 |
| 22 | `20261104-151924-9c11` | 明确指出测试预期的计数有误 | 保留 Unknown 正确，不应拦实现 |

29 次生成的原生 `modelUsage` 是 `claude-haiku-5-5`；4 次确认均是
`claude-sonnet-5-5`，而请求和 run 记录中的模型仍是 `haiku`。后四次使用回放配置的
`--permission-mode plan`。这是可证实的请求/实际模型不一致；plan 与变化同时出现，
尚未通过真实对照证明因果。新回放改用项目已有的 `dontAsk` 只读模式，加 Read/Grep/Glob
允许列表，避免用 plan 执行确认。假 CLI 已确认实际参数接线；真实 CLI 是否仍会换模型尚未验证。

原提示的通用 Finish 要求审查员跑测试，与“控制器负责执行”冲突。模型因此反复尝试被拒的命令，
并在回复中要求审批。新 Finish 明确由控制器执行，审查员只写测试或读证据。

## 哪些是 harness 问题，哪些是模型问题

harness 问题包括 manifest 路径约定不清、把重复文件误归为无效引句、逐字符引用过严、
通用 Finish 指令冲突、确认预算失败只显示笼统 Unknown，以及没有把原生费用与配置估算并列展示。
这些问题已修复并用合成假 CLI 回归覆盖。

模型输出问题包括单元 10 的非原文引用，以及单元 8、22 的错误测试预期；它们继续保留 Unknown。
单元 5、9 的测试是否正确尚无可靠确认。其他尚未执行的测试质量未知。
现有数据不能隔离模型能力与 harness 的影响，也不能证明换强模型会提高抓错率。

## 改动与不变的门槛

| 改动 | 回归检查 |
|---|---|
| 优先读根部 manifest；根部不存在才读 checks/manifest；保存 manifest 和错误诊断 | checks 本地 manifest 真正执行；无效根部不能被备用 manifest 掩盖；缺文件明确记录 |
| 每条引句先校验，再按文件去重执行；保存该文件所有有效引句 | 重复文件只执行一次；第二条有效引句可用于确认；重复条目中夹带非原文仍 Unknown |
| 仅规范化空白、Unicode 标点和 Markdown 反引号，再查原文子串 | Markdown/换行通过并能确认失败；改写、改数字和纯标点仍拒绝 |
| 独立 Finish 禁止审查员自行跑测试 | 对两次实际假 CLI prompt 检查，通用执行提示不再出现 |
| 保留确认错误、每次请求设置和原生费用 | 假原生超预算保留 error 和费用，保持 Unknown；非法确认对象不导致异常 |
| 新增空默认的 `review.tests_model` / `review.tests_effort` | config set 与两次请求都核对；空值沿用 Haiku low |
| 回放 `--reviewer-model`、`--reviewer-effort` 和可重复 `--unit-cap MODEL=USD` | 仓库外独立进程 dry-run；合成树经真实 worker 子进程和假 CLI 验证参数、权限和预算 |
| 行内记录请求覆盖值、单元上限、`by`、`reviewer_calls`、`native_usd` | 保留 29 行和所有 Unknown，按选中模型预留；缺原生费用时记 null |

默认仍是 `read`，两个覆盖项均为空。没有更改抓错/误拦门槛，也没有把测试失败直接当作 issues。
`usd` 保留原有配置估算含义，新增 `native_usd` 表示 CLI 报告的费用，二者不混加。
原生命令上限仍是每次请求的单元 cap/2；CLI 曾在停止时略超过上限，不能保证账单严格不超。

## 第二轮建议与每单元估价

建议首先固定 `--reviewer-model haiku --reviewer-effort low`，只验证 harness 修复后的表现，
不同时换强模型。可用 `--unit-cap haiku=0.15 --budget 4.35`：每次调用预留 $0.075，
29 单元共 $4.35。上限从历史 $0.10 调到 $0.15 必须在第二轮预登记中写明；它是预算配置变化，
不是验收门槛变化。旧输出与新输出必须分开，并以最终提交 pin 真跑。
