## 预算与显式执行

按统筹本次决定，**显式同时提供 `--run --budget` 才能调用模型**；不带动作参数或使用 dry-run 都只打印计划。
`--run` 缺少显式预算会在模型调用前拒绝。主导每次恢复调用都传 `--max-budget-usd L`，默认 **$1.50**；
子任务传 `--max-usd C`，默认 **$1.50**。每题前检查已知花费 `S + L + C ≤ --budget B`，self 的 C 为零；
放不下就记录未开始的任务并停下，记账 Unknown 也停。子任务的后续修复共用该题剩余额度，包装器根据该题累计的子任务、
审查、修复花费，压低每次 run/resume 的上限，不能通过另起一次修复重新取得整笔额度。

计划和 summary 明确报告超限额度 **L+C=$3**、操作上界 **B+L+C**：`--budget 12` 时为 **$15**，
`--budget 15` 时为 **$18**。这是约定的每个角色各容纳一次末次请求超限额度，**不是供应商账单的绝对硬上限**。
CLI 在请求/步骤边界检查（ccx 见 `ccx/delegate.py::_capped`），正在执行的调用可能突破额度；实际超额仍入账，并停止后续调度。
不能把这个操作上界说成账单保证。原先等待供应商硬上限的阻塞已由本次明确的执行策略取代；本单仍没有调用真实模型。

统筹还需要在开跑前提交带最终代码 pin 的预登记；本单未提交的实现和报告不等于已经满足这一条件。

## 固定设计

一局四题，每组各有一个持续的 Claude 会话，使用 Sonnet / medium。每局每组的 UUID、工作区、hub 和隔离
Claude 配置目录均独立。第一次用 `--session-id UUID`，之后三次用 `--resume UUID`，保留会话。
已查本机 **Claude Code 2.1.316 `--help`（2026-11-04）**；没有真跑恢复会话，恢复后的费用计数范围仍未验证。

两组题序相同，按题交错执行，交替调整先跑哪组，同一时间只运行一个主导进程。
`self` 自己实现与检查，不能用 Agent 工具或其他模型；`ccxlong` 必须派给 Codex，省略 `--tradeoff`，沿用现有默认取舍、审查和路由。
两组能看到同样的历史已有测试。最终隐藏判分使用参考提交的测试文件，不送给主导、不写回 `ccx verify`、共享记忆或实际工作区。

现有 `ccx/leadview.py` 只对 clean 结果输出一行；带注意事项的成功结果仍可能展开。
本单的 `p4_receipt.py` 包装器复用 `leadview.line`，捕获完整输出，把成功结果固定成一行收据，隐藏 diff 和审查正文；
失败结果才可显示详情或要求修复。提示明确要求 `ok=true` 后不读文件、diff 或完整结果，也不再跑检查。
提示与假 CLI 测试不能证明真实模型一定遵守。

历史协议限制：`ok=true` 表示执行成功，可能同时检查失败。
[8 单收据核查](2026-11-05-receipt-audit.zh.md) 记录了既用 `DONE:` 又披露失败的转述，以及提示中“ok 就接受”的规则。
紧凑收据现在以展示字段 `headline` 开头，例如 `CHECK_FAILED`；历史提示、评分、结果与验收规则均保留。

每题开始前在**同一路径**重建该题参考提交的父版本，只有一个起始 Git 提交，没有上游历史或 remote；
会话和 hub 保留。这样避免历史任务之间的代码依赖，但测的是上下文累积，不是连续开发：上一题的实现会消失。
清单保留了方向相反的两个 `first_true` 任务，采用上述复位规则；先前对话也可能让后续任务更容易。

执行引擎复用 preflight 的隔离、审计、进程清理、监视与 fingerprint，r5 的 wait-quiet 和产物目录命名，以及
evidence_streams 的脱敏。Codex 使用工作区内的独立 TMP。隐藏测试在另一份临时树运行，判分、diff 和日志保存在
被拒绝读取的工作区外目录。逐行记录每题和每局累计费用/墙钟、审查费用、主导原始费用、每次请求的上下文长度、
上下文增长、缓存读取、审计与 `env_clean`。费用缺失记 Unknown 并停止；失败、中断和已观察到的费用保留。
会话收尾检查保守地应用到该会话全部行。

## 判定与限制

门槛不变：ccxlong 总花费 **≤0.8×self**，做对数 **不少于 self**，每题墙钟中位数 **≤2×self**。
summary 打印分子、分母、比值、尝试/做对分母和每局累计，同时报告全部行与 `env_clean` 行。
缺失、未配对、不完整记账、费用或墙钟的零分母、判分环境失败均保留 Unknown；中断不完整的配对不能 Pass。

**派活和只看一行同时变化，影响没有分开。** 其他限制还有：开发与最终分别来自两个不同库，仓库影响与集合划分没有分开；
样本少、公开历史提交可能已被模型见过、复位工作区不同于日常连续开发、真实遵守程度与 resume 计费未验证。
预算上界属于操作约定，不是账单保证。
没有得出科研结论或产品性能结论。
