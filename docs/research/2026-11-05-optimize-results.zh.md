## 污染与结论边界

**P4 的 LF 假失败。** 当时 Windows 工作区来自 LF 归档检出；本单明确指出这种检出造成验收假失败。
后续预登记要求 CRLF/native 检出并验证基线通过。历史 `env_clean=true` 不证明完整验收命令没有污染。
获准读取的最终行不足以独立定位受影响的 check、次数和可避免花费，这些都是 **Unknown**。
不改写隐藏测试结果，不删行，也不扣猜出来的返工费。记录行口径仍为 Fail；干净重跑是新证据，不能把历史结果追认成 Pass。
[native 检出合同](2026-11-05-p5-contract.zh.md)说明基线检查；本次没有重新执行。

**累计记账 bug。** 开发阶段把恢复会话返回的累计金额当成每次金额相加，重复计算之前轮次。
最终协议按每个会话、每组已校验的累计值取差。L 没有 false 的 `cost_cumulative_check` 或 `session_match` 标记。
本次加总最终每题 `usd`，不再加 `episode_usd` 或累计计数；没有重读事件流、独立复核 token 记账。
见[记账修正说明](2026-11-04-p4-cost-accounting.zh.md)。

**协议与选题。** S 指纹写 concurrency **2**，与一次只跑一个评测的要求不一致。
数字门槛 Fail 不变，但环境等价性、是否干净的最终对比仍 Unknown。
L 的“派活”和“只读一行收据”同时变化，没有分开。第二轮 C 复用 P4 题不能算没见过的新题；
不同版本和题集也不能拼成重复试验。

**收据与外推。** 三份输入不能组成普通 `ok` 收据误报率的分母，该比率及其上界为 Unknown，不能填零。
本报告不新增统计优越性或非劣效结论，只按预登记检查小样本门槛。Windows 记录不证明 macOS/Linux 真机效果。
没有确立新的 P5、第二轮 C/D、真实额度接力、CI 或整个产品的收益。

## 实际建议

这些短任务和中等任务的结果没有证明自动派活能省钱，小任务默认自己做。
不同工具访问、可独立验收的分工、把工作移出受限厂商仍可能有用，但这是待验证用途，本报告没有证明其收益。
便宜首轮或依赖审查的路径要晋升默认，先有独立验收、失败入账和可信的 Unknown 处理。保留负结果，未证实的行为继续显式开启。
