| Attribution | Each group changes one switch or factor; everything else stays at defaults |
| Cost | API-equivalent USD, failed and interrupted runs included |

## 1. Groups in this round

Run G1→G4 in order; the next group starts after the previous group's report.

### G1 Shared-context retest (core claim)
- Change: `--context on` vs `off`.
- Models: codex `gpt-6-luna` low and dsh `deepseek-flash` low (fixed by the script). dsh is the CLI bundled with the
  DeepSeek app; set `CCX_DSH_BIN` to it for the run; it must be logged in.
- Commands: `python scripts/eval/strength_retest.py plan context --dry-run`, then `python scripts/eval/strength_retest.py execute context --run --budget 4 --out <eval dir>/unified-g1`.
- Sample: 7 tasks × 2 agents × 3 reps × 2 arms = 84 runs, paired by task + agent + rep into 42 pairs. The 3 reps of
  a task are not independent, so p is optimistic.
- Differences from last time: same task set; no rework round (the script fixes `--no-escalate --review off`).
- Verdict, in order:
  1. Pairs valid on both sides < 35/42 → Unknown.
  2. With b = pairs where on is right and off wrong, c = the reverse: b − c ≥ 15 and exact McNemar p < 0.05, and on
     cost per success ≤ 1.2× off (not applicable when off has 0 successes) → Pass.
  3. Otherwise Fail.
- Limits: the tasks were used before and the design is best-case; it shows the mechanism works, not typical tasks.
- Script `--budget`: $4 (the script refuses more).

## 4. After a verdict

- Pass: write the report and STATUS. Changing a default or publishing a number first needs a second round
  (separate pre-registration and budget). G4 is diagnostic only.
- Fail: the switch stays default-off; the docs mark it "measured, not recommended" with numbers and a report link
  (as in #302).
- Unknown: state why (too few valid rows, interrupted, ...) and draw no conclusion.
