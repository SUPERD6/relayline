# Phase 4 pre-registration: a long session doing several larger tasks (2026-11-04, written before the run)

[中文](2026-11-04-p4.zh.md) · Translated from the Chinese original; the Chinese text is authoritative.

## Conditions
- Pin `013ac25` (PR #275), separate clone, machine idle, one evaluation at a time. Lead sonnet medium. Codex uses an in-workspace TMP.
- One game is one lead session that does 4 tasks in a row with `--resume`. `self` does them itself; `ccxlong` delegates to Codex and reads only a one-line receipt on success. **Delegating and reading only one line vary together, and their effects are not separated.**
- Tasks: 4 development (more-itertools), 8 final (boltons, 2 games). Selection rules in `scripts/eval/long_selection.json`, chosen without looking at model results. The task code changes are 41 to 179 lines, medium size, not representative of very large tasks. Each task is reset to the parent version: this measures context accumulation, not continuous development.
- Two steps:
  1. **Development dry run**: `--split dev --rounds 1 --budget 4 --tag p4dev`. Only checks the flow (resume, accounting, whether the one-line read is obeyed). No threshold, not evidence. The harness or the lead instructions may be fixed from it; fixes must be written down before the final run, without changing thresholds or tasks.
  2. **Final run**: `--split final --rounds 1 --budget 9 --tag p4final`; write the final pin into this file before starting.

```
python scripts/eval/p4_long_session.py --run --split <dev|final> --rounds 1 --budget <4|9> --tag <p4dev|p4final> --wait-quiet 120 --pin-commit <pin> --codex-workspace-tmp --ext-cache <optimize-loop line 177> --ext-python <same> --codex-home <main dir>/.ccx/eval-codex-home --out <main dir>/.ccx/eval/<tag>-results.jsonl
```

## Metrics
Total cost per game includes the lead, sub-agents, review, fixes, failures and interruptions, API-equivalent dollars. Correct = all hidden tests pass. Wall-clock is the median per task, with the cumulative reported separately. Report both all rows and env_clean rows. Also report the lead's context growth and whether the lead really read only one line.

## Verdict (final run only, in order)
1. Among 16 task rows, env_clean < 12, or env_clean < 6 in either group, or any game not finished: **Unknown**.
2. Threshold A: ccxlong total cost <= 0.8 x self total cost. Threshold B: ccxlong correct >= self correct. Threshold C: ccxlong median wall-clock <= 2 x self median wall-clock.
3. All three pass on all rows = **Pass**; any fails = **Fail**. All rows and clean rows disagree: **Unknown**.
4. One round is only a signal. Only Pass goes on to a phase 5 re-run and only then can public claims be considered. Fail means do not promote cost saving. At most two rounds of changes per item.

## Budget and interruption
Plan cap $15, 1.5x line $22.5. The two steps together have `--budget` $13 and an operational upper bound of $19 (each step can overrun by one last game, L+C = $3); it is not a hard billing cap. Spend is accounted; failures and interruptions are kept. Do not change the thresholds in this file after the run starts.

## Change log (written before the final run; thresholds and tasks unchanged)
The development dry run (a00e507, script recorded $1.007, real about $0.656) only checked the flow: resume attached to the same session, and the lead read only the one-line receipt; task 4 did not run because the reserve was insufficient. Development results are not evidence. The harness was fixed accordingly:
1. The isolation method changed to default flags (same as phases 0 and 3). The old hard-coded config-dir needs user credentials, which the evaluation does not touch. The pre-registration did not state the isolation method.
2. Lead cost is now computed as the difference of cumulative values. With `--resume`, total_cost_usd is cumulative over the session, and the old script summed it; the development ratio 0.81 was really 1.54, biased toward ccxlong. A decreasing cumulative value or a failed check is treated as unknown.
3. Preflight failures print the reason, and the pin prefix is compared.
A limit seen in the development dry run: the failures on three tasks were all hidden tests requiring a TypeError to be raised, which the task text may not state. Tasks are not changed; the report says so.
