## 1. 本轮各组

按 G1→G4 顺序跑，前一组出报告后再开下一组。

### G1 共享上下文重测（主打卖点）
- 改什么：`--context on` 对 `off`。
- 模型：codex `gpt-6-luna` low、dsh `deepseek-flash` low（脚本固定）。dsh 用 DeepSeek 应用自带的 CLI，开跑时设 `CCX_DSH_BIN` 指向它；需要已登录。
- 命令：`python scripts/eval/strength_retest.py plan context --dry-run`，再 `python scripts/eval/strength_retest.py execute context --run --budget 4 --out <评测目录>/unified-g1`。
- 样本：7 题 × 2 个 agent × 3 次 × 2 组 ＝ 84 次运行，按 task + agent + rep 配成 42 对。同题的 3 次不独立，p 值偏乐观。
- 和上次的差别：同一任务集；没有上次的返工轮（脚本固定 `--no-escalate --review off`）。
- 判定（按顺序）：
  1. 两边都有效的对 < 35/42 → Unknown。
  2. on 对、off 错的对数 b，减去 off 对、on 错的 c，b − c ≥ 15，且精确 McNemar p < 0.05；并且 on 每次成功花费 ≤ 1.2 × off（off 成功数为 0 时这一条不适用）→ Pass。
  3. 否则 Fail。
- 局限：题目上次用过，是"最好情况"设计，只说明机制有效，不代表一般任务。
- 脚本 `--budget`：$4（脚本拒绝更高）。

### G2 记忆加样本（主打卖点）
- 改什么：nomem / mem / hubmem / hubstart 四组。
- 模型：codex `gpt-6-luna` low（脚本固定；没有上次的 claude↔codex 双向）。
- 命令：`python scripts/eval/strength_retest.py execute memory --run --budget 3 --out <评测目录>/unified-g2`。
- 样本：72 个单元，每组 18。主比较 mem 对 nomem，按 task + rep 配成 18 对；另两组只作诊断。
- 判定：两边都有效的对 < 15/18 → Unknown；精确 McNemar p < 0.05 且 b > c → Pass（18 对时这要求大约 b − c ≥ 5 且 c 很小）；否则 Fail。
- 局限：6 道题都用过；同题重复不独立。
- 脚本 `--budget`：$3（脚本拒绝更高）。

### G3 便宜首轮 `dispatch.cheap_first`
- 改什么：self 对 ccxcheapfirst。
- 模型：主导 Claude Sonnet medium；子智能体用 `dispatch` 配置的默认档，开跑前从 `--dry-run` 输出抄进报告。
- 命令（一行）：`python scripts/eval/p4_long_session.py --run --split dispatch --arms self,ccxcheapfirst --budget 6.5 --lead-budget .25 --child-budget .5 --tag unified-g3 --pin-commit PIN --ext-cache <EXT_CACHE> --ext-python <EXT_PYTHON> --codex-home <CODEX_HOME> --out <评测目录>/unified-g3 --wait-quiet 10`。开跑前先 `--validate-native` 检查 ext 依赖。
- 样本：6 题，每组 6 个单元，共 12。
- 判定（看全部行，env_clean 子集另报）：
  1. 已跑 ≥ 3 题后升级率 > 30%（从 `dispatch.metrics` 取）→ 停，判 Fail。
  2. 任一组有效单元 < 5 → Unknown。
  3. 做对 ≥ self、花费 ≤ 0.8 × self、墙钟中位 ≤ 2 × self 三条都满足 → Pass；否则 Fail。
- 脚本 `--budget`：$6.5，脚本的运行时上限 $7.25。

### G4 长任务三组（focused_retry）
- 改什么：self / ccxlong / ccxlongcheap，`--native-checkout --focused-retry`。
- 模型：主导 Claude Sonnet medium；ccxlong 子智能体 `gpt-6.1-sol` medium，ccxlongcheap 用 `gpt-6-luna` medium。
- 命令（一行）：`python scripts/eval/p4_long_session.py --run --split final --native-checkout --focused-retry --arms self,ccxlong,ccxlongcheap --budget 10 --tag unified-g4 --pin-commit PIN --ext-cache <EXT_CACHE> --ext-python <EXT_PYTHON> --codex-home <CODEX_HOME> --out <评测目录>/unified-g4 --wait-quiet 10`（dry-run 估 $9.6）。
- 样本：8 题、2 个 episode、3 组，共 24 个任务单元（6 个 Claude 会话）。
- 比较：ccxlong 对 self；ccxlongcheap 对 ccxlong（基准是 ccxlong）。都用 `unified_summary.py p4 --pair`。
- 判定（每对各判，看全部行，env_clean 子集另报）：任一边有效单元 < 6/8 → Unknown；花费 ≤ 0.8 × 基准、做对 ≥ 基准、墙钟中位 ≤ 2 × 基准 → Pass；否则 Fail。
- 局限：8 题都在 p4final 里用过，结果只作诊断，**不据此改默认值**。参考：上次 ccxlong 是 Fail（花费 2.05 倍、墙钟 5.5 倍）。
- 脚本 `--budget`：$10，脚本的运行时上限 $13。
