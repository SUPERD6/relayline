# P0-13：先讨论再实现的一轮小 A/B 预登记

[English](2026-11-03-p13-discuss-prereg.md)

## 假设与固定处理

假设：三家模型的一轮短讨论，可能使设计类任务的做对率提高到足以抵偿额外成本。
独立单位是任务，同一任务的两组构成一对，各自在相同历史父提交的新副本上工作。
6 题 × 2 组 × 1 轮，共 12 个实现单元，串行执行。按下表题目顺序交替安排先跑的组，各有三次先跑。
不根据结果换题、重试或替换单元。

| 组 | 协议 |
| --- | --- |
| `nodiscuss` | 全新 Claude `sonnet`、`medium` 主导，仅有 Bash 工具，直接派一次 `ccx run`。 |
| `discuss` | 脚本先执行 `ccx discuss --with codex,claude,deepseek --rounds 1 --tier T1`，把裁决的结构化结果追加到原简报后；然后相同的新主导派相同配置的 `ccx run`。 |

两组执行者固定为 Codex `gpt-6-luna`、`low`、write 模式。显式关闭评审、升档、换边、执行者子智能体、
worktree、共享会话附件和 A/B 抽样。主导只执行给定命令、等待并报告，不读仓库、不改文件、不重试、不续跑。
主导不会单独收到组名或讨论；执行者通过简报文件接收任务。讨论角色固定为 Codex 提案、Claude 批评、
DeepSeek 裁决（`deepseek` provider，通过 Claude adapter）。使用现有 provider 配置和用户在环境中提供的 key，
脚本不读取或复制凭据。每个单元通过共享 preflight 获取新的题目副本、hub、临时目录和隔离设置。
参与者顺序和 T1 档位固定，不根据结果自动选择。

一轮讨论包括提案、批评、裁决；现有命令可能在同一轮追加格式修复请求，照实保留请求及成本。
讨论未完成、格式未解析、无推荐结论，或主导派发次数不符合协议，都记协议失败，不伪装成成功对照。
仍有分歧时保留分歧，不仅因未达一致就判失败。

## 指标、记账与判定

正确性以原隐藏验收命令的退出码为准，在 agent 之外使用 r5 隔离 pytest 环境评分。
普通隐藏测试失败计为做错，不丢弃。每行保留 `ok`、`pytest`、失败项、协议证据、时间、CLI/配置/题集指纹、
`audit`、`leftovers`、`env_clean`。协议或基础设施错误照实记录，正式结论为 Unknown，不悄悄重跑。
拒绝复用已经有数据的 tag 或工作目录。

每组报告：隐藏测试成功数/题数、API 等价总花费、每成功成本、墙钟秒数、主导 token 和主导花费。
每成功成本为纳入单元的全部成本除以成功数，包含做错实现的成本。
主导 token 指 Sonnet 输入、缓存读取、缓存创建及输出，按唯一消息累加。
讨论轮花费和讨论墙钟单列，同时计入总成本、总墙钟；执行者成本也单列。
缺失的价格或 usage 保留为 `null`，不补零。
单元墙钟包含准备和隐藏评分时间；讨论墙钟仅覆盖讨论命令。
共享 preflight 金丝雀不属于任一组单元；单独预留 $0.04，计入整轮软预算，不分摊到组的每成功成本。
这只是预留值，不是金丝雀实测账单；原始 preflight 证据保存在 `preflight.json`。

正式判定要求：仅一个 tag，恰好六个完整干净配对，均为第 1 轮，无重复、缺失、协议失败或污染单元。
仅当同时满足以下两条，记 **Useful（有用）**：

1. `discuss` 比 `nodiscuss` 至少多做对 2 题，即做对率差至少 2/6。
2. `discuss` 每成功成本不高于 `nodiscuss` 的 1.5 倍。

完整合格数据具备、但任一条件不满足，记 **Negative（负结果）**；覆盖、协议、环境或记账不足则记
**Unknown**。任何一组零成功时，每成功成本没有定义，联合判定记 Unknown，不除零或编造基准。
`summary --include-unclean` 仅展示描述性总数，不能让污染证据支持正结论。
多个 tag 混在一起时为 Unknown；用 `--tag` 选择预登记的一轮。这是实用筛查阈值，不是显著性检验或普遍因果证明。

## 预计成本、运行与产物

固定规划预留：主导每次 $0.025、执行者每次 $0.06、讨论每次 $0.15、preflight $0.04。
总计 12 × ($0.025 + $0.06) + 6 × $0.15 + $0.04 = **$1.96**。
这些是粗略预留，不是实测估计或实时价格。格式重试、长实现和额外开销都可能超出。
`--budget 2` 仅在单元之间检查累计已知成本，正在执行的请求可能超出；提前停下未完成十二单元就记 Unknown，
保留所有行。每次主导另有 CLI 自带的 $0.10 预算。

从仓库根目录干跑（也可在仓库外用脚本绝对路径）：

```powershell
python scripts/eval/p13_discuss.py --dry-run
```

**仅用户批准后**，由统筹确保 `CCX_EVAL_CODEX_HOME` 已指向独立、已登录的评测 home，
并在环境中提供 DeepSeek provider key，再照抄：

```powershell
python scripts/eval/p13_discuss.py run --execute --tag p13-r1 --wait-quiet 30 --budget 2
python scripts/eval/p13_discuss.py summary --tag p13-r1
```

也可显式传 `--codex-home <eval-home>`。开跑前记录批准的命令原文、checkout commit、CLI 版本及环境。
这次变更没有执行或批准上述付费命令。
`--wait-quiet` 复用 r5 的启动前和单元之间等待机制，不授权在忙机器上运行。
共享 `run_checks` 开启 Claude 隔离金丝雀及 Codex shell 金丝雀。
`--force-unclean` 可越过失败的 preflight，但所有行均为污染行，不能满足判定规则。
执行中发现的干扰不会因为之后变安静而抹掉；单元间检查环境和版本漂移。
`--tasks` 只用于子集冒烟，少于六个配对无法满足正式规则。

默认结果：`<main-checkout>/.ccx/eval/p13/p13-results.jsonl`，旁边追加 `p13-run.log`，末行是 `exit=<code>`。
worktree 启动时通过 Git 元数据定位主检出。工作目录默认是系统临时目录下的 `p13-<tag>`；
保留 stream、讨论 JSON 和按题目/组分开的 hub 证据，每个单元结束后移除题目副本。
可用 `--workdir`、`--out` 指定位置。不启动后台进程，脚本串行执行（`jobs=1`）。

## 限制与尚未完成

只有一轮、六道配对题、一种主导/执行配置、一种讨论角色顺序，评测与开发共用机器。
等待与审计可以记录隔离和干扰，不能创造专用机器，也不能消除随机性、缓存或训练数据熟悉程度的影响。
讨论同时增加调用次数、上下文和耗时，差异不能单独归因于某一机制。
不声称统计显著、跨项目通用或科学提升。
用户批准、真实金丝雀、付费实现、实测成本及最终判定均未做。fake 只验证通路与记账，环境刻意标记为污染。
