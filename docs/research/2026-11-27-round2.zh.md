## 异常

1. **A1：1 行无效。** `r2a1-08-duration-parse`，`off` 臂：`invalid_reason` 是「forbidden path in a tool call」。路径审计发现一次 `Glob` 的搜索根是 `--out` 目录（兄弟单元所在处）；该单元用了 13 次工具、结果不对，花费 $0.004062。按规则这一行无效、这一对剔除，所以 n = 47。它有没有读到兄弟单元的文件没核实（审计只检测、不拦截）。剔除这一对对 `off` 臂没有好处。其他组：无效行 0，路径审计命中 0。
2. **A 组的 `--check` 是脚手架默认值，不是变量。** A 组里 ccx 带 `--check "python -m pytest -q"` 跑，题目没有可见测试，所以几乎每个单元 ccx 都记 `check_broken`；它不触发重试或升档，两臂提示词里是同一句话（[#511](https://github.com/SUPERD6/relayline/issues/511)，已写入预登记修改记录）。A 的分析只用隐藏测试的结果。

4. 每个 `results.jsonl` 里每个单元都恰好 1 行 ledger、1 次 attempt（跑完后核对过）。

## 局限

- **只有 Claude 主导。** 所有主导都是 Claude Sonnet medium；其他厂商做主导的情况没覆盖。
- **两种子 agent。** Claude `haiku` low 和 Codex `gpt-6-luna` low。其他子 agent（包括第一轮发现被污染、这一轮没跑的 DeepSeek）和其他 effort 都没覆盖。
- **一台机器、只有 Windows，** 一组 CLI 版本（见上）、一个 PIN；没有 macOS 或 Linux 的结果。
- **合成题是照「必须有这份上下文或笔记才能做对」设计的。** 两个 A 家族测的是：只存在于主导对话或记忆里的约定或笔记，能不能传到子 agent；基线按设计接近 0（48 个里最多对 4 个）。它们说明「信息被需要、又没有别的来源时」机制有效，**不**说明真实任务里有多常出现这种情况，也不能把约 0.85 到 0.92 的效应大小搬到真实工作上。题是一个没参加任何运行的 agent 会话写的；本报告没有记录作者模型，这个设计也看不出出题人是否偏向某个子 agent。
- **每题每臂只跑 1 次。** 题是单位，没估计重复运行的方差。每组 48 对，检验对大效应有把握；这一轮发现不了小效应。
- **neutral（伤害）检查很小：** 8 道题，没有不一致的对。它们没看到伤害，但排除不了很小的伤害。A2 和 A2x 没有 neutral 题。
- **成本结论很窄。** 每次成功成本下降主要是因为 `off` 几乎不成功；两臂总花费接近但不相等：带上下文时 A1 低 19%（$0.1187 对 $0.1472），A1x 高 12%（$0.1162 对 $0.1034）。没有显示、也不声称省钱。
- **hubmem / hubstart 臂只是诊断。** 它们和 `mem` 一样，数据分不出它们的差别。
- **Holm 家族：** A1 + A2（Claude）和 A1x + A2x（Codex）分开，回答不同的结论。
- **B 还没定。** 重跑判定写出来之前，第二轮对便宜先行派发什么也没证明。第一次运行只说明 Windows 命令行长度上限把派发臂弄坏了。
- **这里任何一组都没有证明的：** 真实仓库上对用户的好处、长任务（C 组已移到第三轮）、主导自己额度的花费、其他主导的表现，或任何默认值变更。Pass 是提出默认值变更的前提，不是决定改默认值。
