# P5 检出、验收证据与冷启动工具

[English](2026-11-05-p5-contract.md) · 中文

**仅工程检查。没有真实模型运行、提交或默认晋升。**本文取代[上一份工具说明](2026-11-04-stage5-tools.zh.md)中只校验隐藏测试的八题资格。
A 保持 Unknown、未运行，不增加 `ccx2inst`。

## 统一检出与验收合同

P5 显式采用 `native-git-checkout-v1`：从 Git blob 创建一次提交的临时仓库，再强制 checkout index；
Windows 固定 `core.autocrlf=true`，其他平台固定 false，并尊重 `.gitattributes`。
选题基线、隐藏校验、单元重建和评分采用同一策略。旧 P4 的历史 LF 路径与门槛保留，不修改全局 Git 设置或缓存。

`long_environment.py` 先在**未经修改的父版本上跑完整验收命令**：`ABSOLUTE_PYTHON -m pytest -q -o addopts=`。
解释器固定，cwd 是单元仓库，关闭第三方 pytest 插件自动加载，TMP 位于仓库内专用 `.ccx-eval-tmp-acceptance`，与 P5 单元一致。
只有退出码 0 才继续校验“父版本隐藏测试失败、参考解通过”。失败、超时与排除理由都保留；不修测试或依赖来凑数，
不看模型结果，不用后一次通过静默覆盖负结果。选题 CLI 默认执行这条新规则；旧的程序内调用接口保留兼容路径。

## 完整宿主 check 证据，默认关闭

`CCX_CHECK_ARTIFACTS=DIR` 是显式环境开关，不增加 TOML 键。未设置时，普通 `run_check` 的默认行为和结果不变。
开启后保存完整 stdout/stderr，而非仅保留尾部；`execution.json` 保存命令、解析到的程序、实际 cwd、退出码、TMP，
以及解释器探针的 `sys.executable`、版本与 cwd。探针在验收后用同一个简单 Python 程序和环境启动；
不能据此认定复杂 shell 脚本内部的所有解释器，无法确认的保留 Unknown。写证据失败不改变验收退出码。

harness 逐轮启用，并在清理前将**所有尝试**导出到 `artifacts/<unit>/checks/check-*/`。
输出完整但脱敏；执行元数据按本单要求保留实际本地路径，因此被忽略的本地 artifacts 对外发布前仍需审查路径。
不复制工具 home 的配置、凭据或会话库。收据包装器还会强制使用 P5 指定的验收命令，防止 PATH 漂移悄悄换解释器。

## 显式三组比较

默认仍是 `self,ccxlong`；显式使用 `--arms self,ccxlong,ccxlongcheap` 才加入新组。
`ccxlongcheap` 只改变初始 builder 参数：`--model gpt-6-luna --effort medium`，
任务与验收提示、审查、预算及后续 fallback/升档策略沿用 ccxlong。
实际升档记录在账本 rungs 中，不承诺每次后续尝试仍是 luna；收据包装器对 run/resume 强制首档参数。

核对版本 **codex-cli 0.164.0** 的 `--help`、`exec --help`，支持 `--model`、`-c key=value`。
适配器生成 `-c model_reasoning_effort="medium"`；仓库 T1 是 luna/low，T2 是 sol/medium，本组显式覆盖为 luna/medium。
假 CLI 验证了 argv；账户/模型是否实际支持并成功执行 medium **未运行**，不能只凭帮助认定。

`--gates p5` 列出三组统计，分别将两个 ccx 组与 self 比较，保留原有每对门槛：
十六行、每组八行、四轮一局全部结束，至少十二行干净、每组至少六行，Claude 侧花费比不超过 0.5，做对数不少于 self。
证据不足为 Unknown；总花费比、墙钟中位比仍只作描述。不另造三组联合 Pass 门槛，P4 门槛不变。

当前有效清单 dry-run 排零题。另列明确标为**不可执行的原八题假设估价**：二十四次尝试合计 **$15.213**，
self $6.915、ccxlong $4.149、cheap $4.149。
cheap 暂用普通 ccxlong 的保守规划代理值；luna/medium 的真实上下文、重试和节省均为 **Unknown**，不是实测。
没有提高实际执行预算。

## 冷启动：可见内容，不能拼出不存在的 token 分账

`p5_cold_start.py` 只读指定的 p4final artifacts 和已有 Git 缓存，从主导收据定位 builder，
只统计 **events.0.log**，排除审查和重试。[数据](data/p5-cold-start.json)保留整轮用量及字符估算。

| builder 第一轮 | 读文件输出 token 代理值 | 其他命令输出 token 代理值 |
|---|---:|---:|
| iterutils | 9,425 | 1,674 |
| file/path/names | 9,199 | 8,404 |
| GC/types/trace | 5,296 | 358 |
| IndexedSet | 17,271 | 2,315 |
| mapping | 10,232 | 404 |
| BarrelList | 5,646 | 202 |
| ellipsize | 2,901 | 160 |
| timezone | 2,387 | 200 |

依据是可见输出字符数/4，粗范围为字符数/6 至 /2；混合 shell 命令输出无法完全拆分。
GC 一轮还有提及 AGENTS 的混合输出，代理值 384，不能认定都是 AGENTS 内容。
八个固定父版本的仓库内 **AGENTS.md 都是零个**；自动注入的祖先/全局 AGENTS 仍是 **Unknown**，未检查禁止读取的 home。

首个请求尚无**本次新会话**之前工具返回的读文件/命令输出，这两项来源为零；共享或自动上下文带入的历史文件/命令文本仍为 Unknown。
系统/developer 提示、工具定义和自动上下文没有留存，首请求对应 token 为 **Unknown**。
原生 `turn.completed.usage` 累加整轮多个请求；只减一次文件长度，会把反复进入上下文的内容误算成系统提示。
因此上表不是计费 token 比例，也不是精确的首请求拆分。

`--focused-context` 是默认关闭的最小候选：缩短重复派活说明、指向实现文件、避免全仓库大段读取，保留边界和验收规则。
使用独立 tag，计划与结果行会记录开关。假测试只证明文字缩短和文件入口生效，不能证明省钱。
现有证据不足以支持自动删系统提示/AGENTS 或改默认值。
focused 暂不设第四组，原因是本轮三组固定比较初始模型档位；提示候选另用 tag 对照，避免把两个因素混在一起。

## 离线命令

```bash
python scripts/eval/long_environment.py --manifest scripts/eval/p5_long_selection.json --ext-cache CACHE --ext-python PYTHON --raw-dir RAW --output AUDIT.json
python scripts/eval/p5_long_select.py --ext-cache CACHE --ext-python PYTHON --raw-dir RAW --output NEW_SELECTION.json
python scripts/eval/p4_long_session.py --dry-run --split p5 --gates p5 --arms self,ccxlong,ccxlongcheap
python scripts/eval/p4_long_session.py --dry-run --split p5 --gates p5 --arms self,ccxlong,ccxlongcheap --focused-context --tag p5focused
python scripts/eval/p5_cold_start.py --results P4FINAL.jsonl --artifacts-root ARTIFACT_RUN --ext-cache CACHE --out COLD.json
```

audit 在 accepted 为空时检查清单保留的原审计题；没有任何题时直接报错，不将空校验判为 Pass。
重新选整个候选池可能较慢（逐题完整父版本基线）；本次选择排除，没有扫描新池替换原八题。
