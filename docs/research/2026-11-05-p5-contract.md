## One checkout and acceptance contract

P5 explicitly uses `native-git-checkout-v1`: Git blobs become a fresh one-commit repository, then a forced index
checkout with `core.autocrlf=true` on Windows and `false` elsewhere, respecting `.gitattributes`.
Selection baselines, hidden validation, episode resets and scoring all use this policy. P4 keeps its historical LF
path and gates. No global Git setting or cache is changed.

`long_environment.py` first runs the untouched parent's **whole acceptance command**:
`ABSOLUTE_PYTHON -m pytest -q -o addopts=`. It uses the selected interpreter, repository cwd, disabled third-party
pytest plugin autoload and a dedicated `.ccx-eval-tmp-acceptance` under that repository, as the P5 unit does.
Only exit 0 is eligible; then the injected hidden tests must fail on the parent and pass on the reference.
Every failure, timeout and exclusion stays in the report. No test/dependency is patched, no model outcome is used,
and a retry cannot silently replace a negative result. CLI selection enforces this extra baseline rule; the
legacy programmatic selector remains available for compatibility with previous offline callers.

## Full host-check artifacts, default off

`CCX_CHECK_ARTIFACTS=DIR` is an opt-in environment switch, not a new TOML key. Without it, ordinary `run_check`
results/defaults remain unchanged. Enabled checks retain full stdout/stderr rather than the receipt tail, plus
`execution.json`: command, resolved program, actual cwd, exit, TMP and an interpreter probe's `sys.executable`,
version and cwd. The probe launches the same simple Python program with the same environment immediately after
the check; it cannot establish the interpreter of an arbitrary compound shell script, which remains Unknown.
Artifact write failures do not change acceptance exits or turn failures into passes.

The harness enables this for each turn and exports **all attempts** to `artifacts/<unit>/checks/check-*/` before
cleanup. Output is complete but redacted; execution metadata deliberately retains actual local paths requested
for diagnosis. These ignored local artifacts must not be published without path review. No tool-home config,
credential or transcript folder is copied. The receipt wrapper pins P5's check command even if the lead passes
a different one, so PATH drift cannot silently substitute another check interpreter.

`p5_cold_start.py` reads only the explicit p4final artifacts and existing Git cache. It selects the builder id
from the lead's receipt, then **events.0.log** only, excluding review and retry turns.

Estimate = observed output characters/4, rough range characters/6..characters/2; mixed shell output cannot be
perfectly separated. The GC turn additionally has 384 proxy tokens of mixed output from a command mentioning
AGENTS; it is not established AGENTS content. All eight pinned parents contain **zero repository AGENTS.md**.
Automatic ancestor/global AGENTS remain **Unknown**; no forbidden home was inspected.

The first request has no prior tool-returned file/command output **from this new session** (zero for these sources).
File/command text inherited through shared or automatic context remains Unknown. System/developer
prompts, tool schemas and automatic context were not retained, so their first-request token counts are **Unknown**.
Native `turn.completed.usage` sums all requests in a turn; subtracting each file once would falsely assign repeated
context to the system prompt. These proxies therefore are neither billed-token shares nor an exact cold-start split.

`--focused-context` is an experimental default-off candidate: shorten duplicated delegation wording and point to
the task's implementation files, discouraging repository-wide dumps. It retains boundaries, check and acceptance
rules. Use a separate tag; rows/plans record the flag. Fake tests verify shorter text and file pointers, not savings.
No automatic system/AGENTS deletion or default switch is justified by the current evidence.
No fourth arm is added: the three-arm comparison holds the prompt fixed while varying initial model tier.
The prompt candidate uses a separate tag to avoid mixing those two factors.
