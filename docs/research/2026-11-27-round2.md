What the data says and does not say:

- The `off` / `nomem` arms are almost always wrong (A1 4 of 47, A2 4 of 48): these tasks really need the agreement or
  the remembered note, so the baseline is not near ceiling. The `on` / `mem` arms are almost always right (A1 48 of 48,
  A2 46 of 48). c = 0 in both groups: not one task went from right to wrong.
- The two diagnostic memory arms (`hubmem`, `hubstart`) match `mem` (46 of 48); this round does not separate them.
- Neutral tasks (A1 only; the A2 task file has none): 8 of 8 right in both arms, no discordant pair, so no harm was
  seen. With 8 tasks this cannot rule out a small harm.
- The cost ratio (0.067) is dominated by `off` rarely succeeding: total spend per arm is similar ($0.1187 `on`
  vs $0.1472 `off`), so "cost per success" mostly measures how expensive a wrong answer is, not that context makes a
  task cheaper to run.
- One A1 `off` row was invalid (see "Anomalies"), so A1 has 47 valid pairs, still above the 43 threshold.

## Group B: cheap-first delegation vs doing the work alone

### What B asks

Arm `self`: the lead (Claude Sonnet medium) does the work alone. Arm `ccxcheapfirst2`: the same lead delegates through
ccx with `dispatch.cheap_first = true` and `[check] sensitivity = "escalate"`, first rung Claude `haiku` low, escalation
rung the lead's own model, and a Codex reviewer. 60 new harder tasks (upstream commits plus authored tasks), one run per
task per arm, 120 units. Pass needs correctness non-inferiority (margin 0.15), a per-task cost ratio bound ≤ 0.8, total
cost ratio ≤ 0.8 and median wall-time ratio ≤ 2, in three analyses (valid pairs, all rows, repository-cluster
bootstrap). A group that is stopped is Unknown and is never resumed; a rerun is allowed after an infrastructure fix, from
the start, under a new tag. Full rules: pre-registration, sections 1, 4, 5.

### First formal run (tag `r2-b`, 2026-11-26): stopped, verdict Unknown

- **Stopped.** At 23:02 the run stopped with reason `environment` (rc = 2) after 77 of 120 rows: 38 `self` rows and 39
  `ccxcheapfirst2` rows (the stop came after a `ccxcheapfirst2` unit, so the arms are one row apart). The environment
  check saw an outside `codex.exe` process belonging to another session on the same machine (not a pytest; the
  read-only pytest monitor recorded 0 hits in 248 checks). By pre-registration section 5 a stopped group is **Unknown**.
  Valid pairs were far below the required 54 of 60. Spend was $7.578454 (budget $34.5), with no auth or budget problem.
- **The delegating arm never worked.** All 39 `ccxcheapfirst2` rows failed before any sub-agent started: every ccx
  dispatch returned `could not start claude: [WinError 206]` (Windows "filename or extension too long"). The cause, as filed in
  #585 and addressed by #588 (both still open when this report was written; the operator's own notes call the cause
  "suspected, not verified", and #588 verifies it with fake-CLI tests and reasoning, not with a measured argv length), was the very long `--settings` string ccx passed on the command line; with 60 tasks the
  deny rules grew past the Windows command-line limit, which the development group (8 units) never reached. The sub-agent's event log is empty, ccx
  spend is 0, every dispatch escalated (72 of 72), the lead then failed on its own, and the 39 rows have 0 right
  (script flag `receipt_error`). This is an infrastructure failure of the tested arm, not a result about cheap-first
  delegation.
- **A second fault let the broken arm keep running.** Launch failures (`receipt_error`) were not counted toward
  `--max-invalid-rows 3`, so the group did not stop at the 4th bad row and the arm ran 39 times.
- **A summary inconsistency.** `unified_summary.py p4` counts the 39 receipt-error rows as valid; P4's own invalid-row
  count counts them as invalid.

## Anomalies

1. **A1: one invalid row.** `r2a1-08-duration-parse`, `off` arm: `invalid_reason` "forbidden path in a tool call". The
   path audit found one `Glob` whose search root was the `--out` directory (where the sibling units live); the unit
   made 13 tool calls and ended not ok, spend $0.004062. By the rule, the row is invalid and the pair is dropped, so
   n = 47. Whether the unit read a sibling's files was not verified (the audit detects, it does not block). Dropping the
   pair does not favour the `off` arm. All other groups: 0 invalid rows, 0 path-audit hits.
2. **A groups' `--check` is a scaffold default, not a variable.** ccx runs with `--check "python -m pytest -q"` in
   the A groups, the tasks have no visible tests, so ccx records `check_broken` for almost every unit; it triggers no
   retry or escalation, and both arms get the same sentence in their prompt ([#511](https://github.com/SUPERD6/relayline/issues/511),
   written into the pre-registration change log). The A analysis uses only the hidden-test outcome.
3. **A2's start was delayed.** An outside pytest from another session ran for about 52 seconds while the monitor waited
   for 5 quiet minutes; the group started after that and overlapped no unit.
4. Every `results.jsonl` has exactly one ledger line and one attempt per unit (checked after the runs).

## Limits

- **Claude lead only.** Every lead is Claude Sonnet medium; leads from other vendors are not covered.
- **Two sub-agent models.** Claude `haiku` low and Codex `gpt-6-luna` low. Other sub-agents (including DeepSeek, which
  round 1 found contaminated and this round did not run) and other effort levels are not covered.
- **One machine, Windows only,** one set of CLI versions (above), one pin; no macOS or Linux result.
- **Synthetic tasks built so that the context or note is necessary.** Both A families test whether an agreement or note
  that only exists in the lead's transcript or in memory is passed on; the baseline is near 0 by design (4 or fewer
  right of 48). They show that the mechanism works when the information is needed and is not available otherwise;
  they do **not** say how often real tasks have that property, and the size of the effect (about 0.85 to 0.92) will not
  carry over to real work. The tasks were written by an agent session that took part in no run; this report does not
  record the author model, and this design cannot show whether authorship favours any sub-agent.
- **One run per task per arm.** The task is the unit; no repeat-run variance is estimated. The sample is 48 pairs per
  group, so the tests have power for large effects; this round cannot detect small ones.
- **Neutral (harm) checks are small:** 8 tasks, no discordant pair. They show no harm; they do not exclude a small one.
  A2 and A2x have no neutral tasks.
- **Cost claims are narrow.** Cost per success falls mostly because `off` almost never succeeds. Total spend
  per arm is close but not equal: with context it is 19% lower in A1 ($0.1187 vs $0.1472) and 12% higher in A1x ($0.1162
  vs $0.1034). No saving is shown or claimed.
- **The hubmem / hubstart arms are diagnostics.** They matched `mem`; the data does not separate them.
- **Holm families:** A1 + A2 (Claude) and A1x + A2x (Codex) are separate and answer different claims.
- **B is undecided.** Round 2 shows nothing about cheap-first delegation until the rerun's verdict is written. The first run
  shows only that a Windows command-line limit broke the delegating arm.
- **Not shown by any group here:** end-user benefit on real repositories, long tasks (group C was moved to round 3),
  token cost for the lead's own quota, behaviour under other leads, or any default change. A Pass is a prerequisite for
  proposing a default change, not a decision to make one.
