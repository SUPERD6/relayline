## 夹具与观察

`python scripts/benchmark_hook_report.py` 在临时目录创建 5 万行旧判定账本、200 个各 2501 行的对话文件，
以及 5,000,012 字节的 JSON 文件。顺序重复三次。旧判定会经过全历史信任和排除逻辑，同时避免节省估算的
bootstrap 掩盖读取成本。报告不含主导用量。不读真实账本、凭据、用户主目录或真实模型 CLI。
归档使用 `tests/fakes/fake_codex.py`。

| 路径 | 改前，ms（三次） | 改后，ms（三次） | 改前 → 改后中位数，ms |
|---|---|---|---|
| 无主导用量报告 | 397.681、336.414、336.007 | 114.597、97.134、95.121 | 336.414 → 97.134 |
| 对话查找 | 1172.622、85.253、88.622 | 1212.970、76.792、75.849 | 88.622 → 76.792 |
| 同一个 Reader 读 JSON | 10.021、0.097、0.052 | 9.931、0.114、0.056 | 0.097 → 0.114 |
| 钩子路径归档，14 次假 CLI 调用 | 1010.290、913.609、897.876 | 5.846、4.773、4.801 | 913.609 → 4.801 |

报告、查找和 JSON 的初始基线在修改前执行。归档基线在修改后重建：用 `--archive-mode sync` 同步调用
未修改的原函数 `archive.auto(p)`。这一项只比较钩子的调度等待，不表示归档本身更快；三次各完成 14 条归档，
等待归档完成放在计时之外。冷启动查找仍约 1.2 秒。JSON 已有 stat 缓存，代码未改；微小差异不能说明提升。
文件系统缓存和机器负载都会影响数字。有一次中间计时与相关测试重叠，未纳入表格。

最终脚本默认 `--archive-mode auto`：只有新版模块存在时才导入后台 worker，旧版用同步调用。
已把完全相同的脚本复制到临时 `git archive HEAD` 源码（没有 `archive_worker.py`）运行完整夹具成功。
单次复跑：报告 420.379 ms、查找 1236.704 ms、JSON 8.908 ms、同步归档 1058.422 ms，14 条归档全部完成。
这验证脚本兼容改前源码；单次复跑不替代表格里的三次观察。

## 实现与检查

报告使用仅在当前调用内有效的进程内账本快照，嵌套的准确率和 trial 统计共用它；正常退出和异常都会清除。
沿用原报告需要主导用量时才读取的规则；活动 trial 的已发布段落仍需读取对应主导成本。
对话发现只缓存 Codex 文件第一行元数据，最多 256 项，mtime、大小、inode、ctime 变化就失效。
每次仍查目录，因此新增、删除的对话可见。

钩子把现有超时用于可注入时钟的内部预算。每个提示段完成后保存完整文本格式，预算用完跳过后续步骤。
读取卡住时仍由原硬超时终止，先输出已有完整文本，再尝试写超时日志。没有提示才输出空内容。
正常输出逐字节不变。内部预算主动退出不计入硬超时次数。

归档通过独立后台进程执行，标准输入输出均为空设备，关闭继承描述符，复用现有无窗口后台参数。
父进程存活时由 daemon 等待线程回收子进程。后台进程复用 ability 模块的 OS 锁实现，另用 `archive.lock`；
遇忙跳过，崩溃由 OS 释放锁。归档选择和记账规则不变。启动失败不影响钩子输出。

相关测试检查 JSON、HTML/文本完全一致，主导用量开关两种情况下的旧版本 SHA-256 快照、账本只全量读一次、
全历史排除和信任、快照清除、假时钟预算、硬超时保留提示、缓存失效、已有 JSON 缓存、归档锁及启动回收参数。
子进程测试从仓库外执行 `ccx mem delta`：一项推进假时钟，一项等待真实后台进程用假 CLI 完成归档并验证幂等性。
现有报告测试也从仓库外执行 report CLI。

验证结果：报告、归档、对话、ability、钩子相关测试 164 项通过；补充的钩子、UI、trial 测试 112 项通过，
13 项浏览器或平台相关检查跳过。最后本单专项测试 10 项通过，包含独立进程的 OS 锁检查。
`scripts/collect_changes.py --check` 和 `git diff --check` 通过。未跑全量，留给统筹验收。

评审修正：开局调度不再读取 `CCX_NO_AUTO_ARCHIVE`，与原 `archive.auto` 语义一致；该变量仍控制运行后归档。
统筹已授权只调整 `tests/test_sessions.py::TestOneShotAndArchive::test_auto_archive_at_session_start`：
钩子返回后轮询完整归档日志行，最多等待 60 秒，再执行原有断言。原断言、测试环境和假 CLI 均不变，
没有改其他既有测试。新增子进程回归用 socket 信号阻塞假归档，先观察到钩子返回且归档尚未完成，再主动放行并检查完成。
